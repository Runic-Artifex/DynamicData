# Runic fork differences

Intentional differences from [reactivemarbles/DynamicData](https://github.com/reactivemarbles/DynamicData)
that must survive upstream merges. Keep IDs stable. Update an entry in the same
change that adds, changes or removes a difference; when upstream provides an
equivalent, remove the adaptation but keep its regression tests, and mark the
entry `retired`. Upstream status is as last reviewed; open gaps are tracked as
[fork issues](https://github.com/Runic-Artifex/DynamicData/issues).

| DD-043 | List and cache `ExpireAfter` and `ToObservableChangeSet`, and list `Filter` with predicate state, deliver through delivery queues without holding their gates; source `ExpireAfter` publishes expired items after the source edit commits, not from inside it. | DD-044 | Primitives flavour: internal replacements in the root `DynamicData` namespace take precedence over ReactiveUI.Primitives' extension methods for library call sites and follow the System.Reactive contract: `Scan` ([ScanExtensions.cs](../src/DynamicData/Internal/ScanExtensions.cs)), `Do`, `DistinctUntilChanged` and `CombineLatest` with a result selector deliver callback, comparer and selector exceptions as `OnError`; `SubscribeSafe(observer)` lets an exception thrown by the observer's `OnNext` propagate to the producer (ending that subscription) instead of converting it to `OnError`. Callback failures (for example `OnItemAdded`, `ForEachChange`, the `WhenChanged` selector) therefore reach `OnError`, and a subscriber's own exception is thrown to the editing caller, as in the System.Reactive flavour. In both flavours, operators that subscribe callbacks (`Filter` with a dynamic predicate, predicate state or reapply signal, `MergeChangeSets`, the dynamic `Group`, `ExpireAfter`, `OfType`, `AsyncDisposeMany`, `ToObservableChangeSet`, `TransformOnObservable`/`MergeManyChangeSets` and the other `CacheParentSubscription` operators, and the lock-free `AsObservableCache`) use [OperatorSubscription.cs](../src/DynamicData/Internal/OperatorSubscription.cs) instead of the static `PrimitivesLinqExtensions.SubscribeSafe(...)` (#25): an exception thrown by the operator's own logic (predicates, selectors, comparers, item disposal) is still delivered as `OnError`, while an exception thrown by the downstream subscriber is thrown to the producer and detaches that subscription, as System.Reactive's `Observable.Create` does. List and cache `MergeMany` (and so `WhenValueChanged`, `WhenPropertyChanged` and `FilterOnObservable`) guard their subscriber the same way, and a subscriber exception thrown at a value a child emits while it is being subscribed (`Observable.Return`, `WhenValueChanged` with its initial value), which reaches the subscriber inside `SubscribeMany`'s transform factory, is carried past that factory by `SubscriberFaultRelay` in [OperatorSubscription.cs](../src/DynamicData/Internal/OperatorSubscription.cs) and thrown to the producer once the source change has been processed; cache `AutoRefreshOnObservable` (and cache `FilterOnObservable`, built on it) throws the subscriber's exception instead of delivering it as `OnError`, and list `FilterOnObservable` rethrows one that System.Reactive's connectable `Replay` would have converted (#34). Primitives operators that dispose themselves before rethrowing a downstream exception (`Defer`, `Take`, `Skip`, `SkipWhile`, `StartWith`, `Using`, `Catch`) are kept: without the conversion they end the subscription like System.Reactive's subscription safeguard. The System.Reactive flavour keeps System.Reactive's operators. A subscriber exception thrown at a value of the initial snapshot is thrown from `Subscribe` in both flavours and leaves nothing subscribed. Operators that subscribe several inputs dispose the inputs they subscribed before it: the merge helpers behind cache and list `Sort`, `Page`, `Virtualise`, `SortAndPage`, `SortAndVirtualize` and the other operators with parameter observables, the cache joins, static and dynamic `And`/`Or`/`Xor`/`Except`, `SubscribeMany` (and so `MergeMany`, `MergeChangeSets`, `MergeManyChangeSets` and `TransformMany`), dynamic `Filter`, `Filter` with predicate state, `BatchIf`, `BufferIf`, dynamic `Group` and cache `AutoRefreshOnObservable` ([#36](https://github.com/Runic-Artifex/DynamicData/issues/36)), and cache `Group` with a result group source ([#39](https://github.com/Runic-Artifex/DynamicData/issues/39)). `SubscribeMany` owns each subscription its factory returns until it is disposed, so one made while `SubscribeMany` is disposed from inside the factory, as a `MergeMany` subscriber exception at a child's value does, is disposed too ([OwnedSubscriptions.cs](../src/DynamicData/Internal/OwnedSubscriptions.cs), [#39](https://github.com/Runic-Artifex/DynamicData/issues/39)). The delivery queues, the unsynchronized merge helpers and the subscriber guard record the exception their observer threw, and throw it again instead of delivering it when a System.Reactive subscribe safeguard hands it back to them as `OnError` on the same thread (`DeliveryFault` in [OperatorSubscription.cs](../src/DynamicData/Internal/OperatorSubscription.cs), [#37](https://github.com/Runic-Artifex/DynamicData/issues/37)). Static cache `And`/`Or`/`Xor`/`Except` guard their subscriber and no longer catch its exception. | Primitives 8.4/9.0 `Scan`, `Do`, `DistinctUntilChanged` and `CombineLatest` throw callback exceptions to the producer; `SubscribeSafe` converts observer exceptions to `OnError`, which an upstream `Defer`, `Take`, `Skip`, `DistinctUntilChanged` (or `Scan`) that had disposed itself before rethrowing then dropped. Failures in `Transform` factories, `Sum`/`Maximum` selectors and similar operators (#17), and in callbacks and subscribers downstream of most operators (#19), were lost, converted or thrown to the editor. The static `SubscribeSafe(source, onNext, ...)` delivered a subscriber's exception back to it as `OnError` (Primitives) or lost it (ReactiveUI.Primitives.Reactive), and `ToObservableChangeSet` and `OfType` caught it themselves (#25). List and cache `MergeMany` delivered a subscriber exception thrown at a value a child emitted while being subscribed as `OnError` (Primitives) or lost it (System.Reactive: Rx's `Scan` delivered it as `OnError` after the subscription had detached), and cache `AutoRefreshOnObservable` delivered every subscriber exception as `OnError` (#34). A subscriber exception at the initial snapshot left the inputs subscribed before it attached to their sources, which kept the subscriber reachable: cache `InnerJoin`, cache and list dynamic `Or` and list `BufferIf`, and most multi-input operators whose earlier input stayed live (#36). A subscription `SubscribeMany`'s factory returned while `SubscribeMany` was being disposed from inside it never reached `DisposeMany` and stayed attached to its source: in the System.Reactive flavour, the first source of cache dynamic `And`/`Or`/`Xor`/`Except` over an observable list stayed subscribed; cache `Group` with a result group source left its source connected in both flavours (#39). In the System.Reactive flavour, `Observable.Create` and `SubscribeSafe` deliver an exception thrown while they subscribe as `OnError` unless their own observer threw it; the exception had reached the subscriber through another path (a shared queue delivering another input's value, a `MergeMany` child subscribed in `SubscribeMany`'s factory, `Concat` subscribing an inner source), so the `OnError` reached the queue, guard or observer that had already thrown, which dropped it, and `Subscribe` returned normally: cache `SortAndPage`, `TransformAsync` with forced transforms, cache and list `MergeMany`, `MergeChangeSets` of an observable of sources and list dynamic `Or` (#37). Static cache `And`/`Or`/`Xor`/`Except` caught every subscriber exception and delivered it as `OnError` (Primitives) or lost it (System.Reactive). | Fork only (Primitives flavour; the operator subscriptions of #25 and the `MergeMany`/`AutoRefreshOnObservable` routing of #34 in both flavours; #36, #37, #39 and the static cache combiners in both flavours). |
| DD-045 | Queue-serialized operators with several inputs also deliver their output through their shared delivery queue: cache `Sort` with comparer changes or resorting, `Page`, `Virtualise`, `SortAndPage`, `SortAndVirtualize`, `Transform`/`TransformAsync` with forced transforms, `BatchIf`, `Group` and `GroupWithImmutableState` with a regrouper, and dynamic `Group`, `InnerJoin`, `LeftJoin`, `RightJoin`, `FullJoin`, dynamic `And`/`Or`/`Xor`/`Except`, `MergeManyChangeSets` (to cache or list changes, with or without a source comparer), `TransformOnObservable`, `GroupOnObservable`, `TransformManyAsync`, `TransformMany` with observable children, `QueryWhenChanged` with an item trigger and `TransformToTree`; list `Sort`, `Page`, `Virtualise`, dynamic `Filter`, `Filter` with predicate state, `BufferIf`, `AutoRefresh`, static and dynamic `And`/`Or`/`Xor`/`Except`, `MergeChangeSets`, `MergeMany`, `MergeManyChangeSets` (to list or cache changes), `TransformMany` with observable children and `GroupWithImmutableState` with a regrouper. A notification an observer causes through another input of the same operator, for example by writing into its source, is delivered after the observer returns instead of re-entrantly; cache `BatchIf` starts the next batch before publishing one. | The shared queue delivers a notification raised on its delivering thread inline, so such feedback reached the observer inside the delivery still running (an Rx grammar violation) and `BatchIf` published batched changes twice (fork issues [#24](https://github.com/Runic-Artifex/DynamicData/issues/24) and [#30](https://github.com/Runic-Artifex/DynamicData/issues/30), follow-up to DD-016). | Fork only; upstream's shared queue delivers same-thread re-entrant notifications inline. |
| DD-046 | Cache grouping publishes the removal of an item that moves to another group before any group publishes its addition. `Group` (also with a regrouper, `GroupOnProperty` and the dynamic selector or regrouper) removes the moved items of an input from their old group caches and publishes those removals first, so a group that loses items to another group and also changes otherwise publishes two changesets for that input; `GroupOnObservable` does the same with the updated items of a source changeset; when an item is otherwise added to a group suspended before the one it left, the suspended changes are published first. Dynamic `Group` and `GroupOnObservable` publish a group's pending changes before disposing it once it is empty. Cache `TransformMany` emits a changeset's removals before its additions and updates, so a child key that moves between parents within one changeset (for example between `GroupWithImmutableState` groups) is kept. | Merging the groups again with `MergeMany(g => g.Cache.Connect())` or `TransformMany` applied the old group's removal after the new group's addition and lost the item, even single-threaded; a group disposed while suspended dropped the removal of its last items, which stayed in the merged result (fork issue [#29](https://github.com/Runic-Artifex/DynamicData/issues/29), follow-up to DD-045). | Fork only; upstream groups publish each group's changes as one changeset, in the order the groups were suspended. |
