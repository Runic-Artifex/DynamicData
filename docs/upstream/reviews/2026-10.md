## Public behavior choices

The reviewed API snapshots add 25 members per flavor: 20 SumImmutable overloads
(cache/list, five numeric types with nullable variants), two default-comparer
ToSortedCollection overloads, one modern contextual Switch overload, list Batch
and the test aggregator's SortedItems property. Existing signatures are unchanged;
Avg and queue/terminal repairs add no public members.

Terminal repair is operator-specific. Absent optional sort/regroup controls may
use Empty so they do not prevent completion; explicitly supplied controls retain
their documented lifetime and errors. Dynamic merge/combine work accounts for
parent and active children separately. MergeMany child failures now deliberately
terminate with OnError instead of being swallowed; this is a public behavior
change. AutoRefreshOnObservable's custom child errors retain their existing
swallowing behavior; a MergeMany repair does not silently change that policy.
Source-dominant binding/tree operators and either-source-completes
specified grouping must preserve synchronous snapshots before termination.
The reviewed cache/list topic contracts below pass the final local matrix;
hosted Linux/Windows evidence is tracked by the linked PR checks.

| Operator family | Reviewed lifetime / failure contract |
| --- | --- |
| Cache BatchIf / list BufferIf | Source completion flushes pending changes once and completes. Source or control errors discard pending changes and fail. List pause-control completion alone keeps the source alive. |
| Static Combine | Serialize input changes; complete after every source, including immediate completion for zero sources. |
| Dynamic combine / MergeMany families | Track parent and active children; removed children release their completion wait and subscription. First parent/child error terminates. Child replacement removes the old snapshot before adding a synchronous new snapshot. Cache dynamic child input is serialized before cloning its changes. |
| Cache/list Sort and grouping with optional controls | Absent controls use Empty. Supplied comparer/resort/regroup controls keep their merge lifetime and forward errors; source completion alone does not imply completion. |
| Specified cache grouping | Either input completing ends the result and tears down subscriptions; preserve the synchronous initial snapshot. |
| Cache SortAndBind / Tree | Source determines completion; SortAndBind comparer errors still fail. Wire the tree graph before connecting its published source so synchronous contents survive. |
| BindPaged / BindVirtualized / Watch / list QueryWhenChanged | Forward completion and errors; Watch disposal is silent. Query collection state is per subscription, including sorted/extrema queries. Both inferred and supplied binding-option paths are covered. |
| MonitorStatus | Pending/Loaded then Completed followed by completion, or Errored followed by the original error, including synchronous terminal sources. |
| List DisposeMany / cache AsyncDisposeMany | Notify downstream before releasing removed instances. List finally cleanup and detached finalization protect ownership when callbacks terminate or throw. AsyncDisposeMany retains its separate awaited disposal-completion channel. |
| WhenValueChanged / WhenPropertyChanged / WhenAnyPropertyChanged | Their MergeMany-based child failures now propagate. AutoRefreshOnObservable retains its separate custom-child error policy. |

Do not treat metadata-free Switch clear batches as valid contextual viewport
messages. For Runic presentations, switch keyed feeds before each independent
SortAndVirtualize. The convenience overload solves selection and clearing; it
does not implement context-preserving or atomic handoff.

Direct mutable Sum retains projections by cache key or list occurrence, O(n)
state per subscription. Cache changes use keyed lookup; list indexed shifts and
indexless reference-first/equality searches can cost O(n). Update/Replace/Refresh
records the new instance/projection before checking equality; unchanged numeric
projections skip arithmetic, preserving cancellation and unchanged infinity.
IAggregateChangeSet Sum remains stateless because Refresh details are already
lost. SumImmutable avoids projection state when values stay immutable: removal
evaluates the selector again, while Refresh/Moved does not. It is unsafe for
mutable rows. Nullable Sum projects null to zero; integral arithmetic retains
unchecked overflow and decimal checked overflow. Actual nonfinite numeric
changes retain ordinary floating arithmetic limits.

Extrema retain the current collection, recomputing in O(n) for replacement,
removal or Refresh batches; pure additions update the cached extremum
incrementally. Unchanged results are suppressed. This does not add MaximumBy or
MinimumBy. StdDev's central-moment formula is unchanged: decimal moments must
fit decimal range and ordinary floating rounding/nonfinite limits remain
independent of mutable refresh handling.

The Avg repair projects direct cache/list inputs before aggregation, preserving
key/index Refresh and occurrence-specific removals; ordinary direct batches do
not rescan the collection. An IAggregateChangeSet has lost keys, indexes and
Refresh metadata. Its Avg path retains projections and treats an empty batch as
an O(n) invalidation of all occurrences, but cannot reconstruct Refresh mixed
with membership changes or indexed removal of repeated references with different
stored projections. Use direct overloads for those cases. Nullable projections
contribute zero and still count in the denominator. Changed or removed nonfinite
floating values can leave arithmetic NaN while other items remain; the repair
does not supply a general compensated-sum algorithm.

The retained [single-outlier Sort benchmark](../../../src/DynamicData.Benchmarks/List/SortSingleOutlier.cs)
uses a full 100,000-row list with reset threshold disabled; it mutates the first
row to sort last, then sends either a resort or comparer notification. Baseline
emission was 99,999 moves, about 12.1 MB managed allocation and 1,966,659 bytes of
synthetic JSON; corrected emission was one move and 13 synthetic JSON bytes.
Final current-thread probes measured 160 B in both flavors; an earlier Reactive
run measured 8,328 B, so constant allocation is not established. Synthetic JSON
uses the fixture's `[Id, previousIndex, currentIndex]` format. Three noisy benchmark samples measured
baseline resort/comparer means of 4.339/11.434 s versus corrected 1.607/1.599 ms.
The reported baseline error intervals exceeded those means; timing ratios are
diagnostic rather than precise estimates.
BenchmarkDotNet 0.15.8 MemoryDiagnoser reported 11,814.3 KB versus 200 B at
100,000 rows. It used an out-of-process job, one warmup, three iterations,
invocation/unroll counts of one, on NixOS 26.11 Linux x64/i9-12900K,
SDK 10.0.401/runtime 10.0.12 and Primitives 9.0.0. Baseline source was
`b9c85580` plus the new identical benchmark/probe fixtures. Corrected source was
`38c51159` plus then-uncommitted Sort/benchmark content later committed in
`5459b07a`; that measurement does not represent a clean checkout of the later
commit including its additional test-only fixture.
This bounded single-outlier workload excludes viewport selection, downstream
binding/browser work and Runic serialization/bridge delivery; synthetic byte
counts are not an end-to-end measurement. It does not establish optimal general
sorting or justify snapshot fallback.

InitialBuffer's [retained lifecycle fixture](../../../src/DynamicData.Tests/BufferInitialLifecycleFixture.cs)
at `f44177f8` uses a one-tick real window: no schedule while idle, one schedule
after the first batch, and scheduling allocation below a broad 256,000 B guard.
It also invokes captured cancelled callbacks to verify terminal silence. These
checks detect recurring-timer work and late delivery; they do not establish a
throughput or CPU-utilization benchmark.

The RemoveKey five-sample local timings have no CPU isolation or confidence intervals.
They establish bounded diagnostic costs, not a general speedup, worst-case
guarantee, Runic bridge improvement or native input-to-paint result. Functional
replay or ABBA checks do not measure move amplification or allocation improvements.
